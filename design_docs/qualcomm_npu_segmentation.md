# Qualcomm NPU Segmentation

## At a glance

[`Collect Unshelve Episodes - Grasp Scout (NPU)`](../src/picknik_009_ur5e_2f85_hw_config/objectives/collect_unshelve_episodes_-_grasp_scout_npu.xml) is `Collect Unshelve Episodes - Grasp Scout` for a Qualcomm Dragonwing board (the IQ-9075 EVK `iq9-1`), and [`Collect Unshelve Episodes - Right Bag (NPU)`](../src/picknik_009_ur5e_2f85_hw_config/objectives/collect_unshelve_episodes_-_right_bag_npu.xml) is the same for the Gemini `- Right Bag` favourite. Each runs the same collection as its original, but the 2F-85 pick's SAM3 segmentations run on the board's Hexagon NPU instead of its CPU. It does that by passing a Qualcomm AI Hub export's bundle manifest down to the 2F-85 `Plan Shelf Pick` and `Execute Shelf Pick`, through the `sam_model_package` / `sam_model_bundle_manifest` ports that `Collect Unshelve Episodes`, the 2F-85 `Unshelve Shopping List` and `Unshelve Product Loop` now forward (see `src/shelf_stocking/design_docs/unshelve_collection.md`). The export lives in this workspace's `aihub/sam3/`, which is git-ignored: it is made on the board and never committed. [`Experimental Collect Unshelve Episodes`](../src/picknik_009_ur5e_2f85_hw_config/objectives/experimental_collect_unshelve_episodes.xml) (`xExperimental - Kristen`) is the `- Right Bag (NPU)` favourite with speed and debugging changes: the carry goes straight to the bag, the free-space moves (views, approach, carry) run at higher velocity and acceleration scales, and only the jello and pudding are re-measured at the pre-grasp (their `exemplars.yaml` entries ask for it), which saves the second SAM3 pass on the products with more finger clearance. It also skips the lift-and-weigh grasp check, which failed a held jello, so a missed grasp is only noticed at the bag. Hard acceleration while carrying has tripped the UR's C157 shoulder protective stop before, so raise its acceleration in small steps. It needs the same export.

The host and export steps are MoveIt Pro's own guide, "Configure Qualcomm Dragonwing" (`src/docs/docs/how_to/computer_configuration/configure_qualcomm_dragonwing/` in the `moveit_pro` repo). Read the copy at the tag that matches the installed Pro, not `main` (see below).

## Why this shape

- **A port, not a config override.** `main` of the Pro docs describes `objectives.model_bundle_overrides` in `config.yaml`, which swaps a shipped manifest for an export with no Objective edits. That is newer than Pro 10.2.0, which `iq9-1` runs, and is not in its image. On 10.2.0 the only switch is the `model_bundle_manifest` port of each `GetMasks2DFromExemplar`. When a Pro release with the override reaches the board, this favourite and the ports can go, and a hw config `config.yaml` entry does the job.
- **A separate favourite, not a changed default.** The vendored four-graph bundle is what NVIDIA PCs run (on CUDA), and an AI Hub export holds QNN context binaries that only a Qualcomm NPU of the chipset it was compiled for can run. The UI does not pass Objective inputs, so the choice has to be fixed in a favourite. Keeping the shared favourites on the default means the laptop is unchanged. The Grasp Scout twin copies its original's other settings, so a change to one has to be made to both; the Right Bag twin keeps the bag side but runs without recording or the pause before the close, for trying the NPU path.
- **Ported from `moveit_pro_flexiv_ws`.** Its `add-orbbec-gemini335l` branch (the Qualcomm demo) put the same two ports on `Find Object On Shelf`, with the default on the shipped bundle and exports in a git-ignored `aihub/`. The names match so the two workspaces read alike.

## Notes and gotchas

- **Compile for the QAIRT version the Pro image ships, not AI Hub's latest.** A QNN context binary cannot be loaded by QNN libraries older than the QAIRT that compiled it, and the failure only shows at the first segmentation, as `Failed to create context from binary ... QNN_CONTEXT_ERROR_INVALID_ARGUMENT` followed by a CPU fallback that cannot run an `EPContext` node. `qai-hub-models` compiles with AI Hub's newest QAIRT by default, which on 2026-11-19 was one release ahead of the image. Read the image's version from `libQnnHtp.so` in the Runtime's `onnxruntime_qnn` Python package, then pin it with `--compile-options "--qairt_version <major.minor>"` (`qai_hub.get_frameworks()` lists what AI Hub offers). The export's `metadata.json` records the QAIRT it was compiled with. Re-export whenever a Pro upgrade changes the image's QNN libraries.
- **Text prompts only.** AI Hub splits SAM3 into a vision backbone and a head with no geometry encoder, so its manifest declares the `moveit_pro.sam3_text.v1` graph ABI and a request with bounding boxes fails. Every segmentation the 2F-85 pick makes is a text prompt. Do not pass these ports to a node that sends boxes or an exemplar image.
- **The manifest is written by hand beside the export.** AI Hub writes a small `.onnx` plus a context binary per graph; the manifest names the two `.onnx` files and their `sha256`. The digest covers the `.onnx` file only, not the binary beside it. Paths must stay inside the manifest's directory with symlinks followed, so the export has to be copied into `aihub/sam3/`, not linked from elsewhere on the host.
- **The Runtime only sees the workspace.** The path in the favourite is the workspace as the Runtime mounts it (under the Runtime user's home), with an empty `sam_model_package` so `GetMasks2DFromExemplar` treats it as a path. An export outside the workspace is invisible to the Runtime.
- **On a PC without the export it fails at the first segmentation,** with the manifest "could not be resolved". That is the signal to run `Collect Unshelve Episodes - Grasp Scout` instead; there is deliberately no fallback to the CPU bundle, which would turn a missing export into a silent, much slower run.
- **The export needs the gated `facebook/sam3` weights.** `qai-hub-models export sam3` builds the model locally from Meta's checkpoint before uploading it to AI Hub, so it needs a Hugging Face login that Meta has approved for `facebook/sam3`. Qualcomm publishes no pre-exported SAM3 (licensing), and its `qualcomm/Segment-Anything-Model-3` Hugging Face page has no model files. The Pro guide does not mention the gate. The SAM3 recipe and the `qai-hub-models` command only exist in newer `qai-hub-models` releases; an older one installs without either.
- **Confirm the NPU is in use** in the Desktop App's Debugging → GPU Status after a run: ML Inference reads Accelerated with `QNNExecutionProvider`. The runtime log also prints `Selected ONNX execution provider:` once per SAM3 graph loaded; `CPUExecutionProvider` there means that run used the vendored bundle, usually because a non-NPU favourite was started.
- **The GraspScout trial server's own SAM3 still runs on the CPU, so only the Gemini twin is fast on the board.** The server loads the vendored encoder and decoder ONNX itself, with stored prompt embeddings, and only has NVIDIA and AMD providers; on the IQ-9075 one `/detect` takes longer than `GetPointsFromGraspScout`'s timeout. The AI Hub export cannot be dropped in, because its graphs are split differently (a backbone plus a head that takes prompt tokens). Making the server use the NPU is a change to the trial bundle, which is its owner's call. The Grasp Scout twin speeds up the Pro side of the pick only.
- **Each SAM3 node loads its own copy of the model** on its first tick (`model_bundle_manifests.md` in the submodule covers the latch), so a pick that reaches the pre-grasp segmentations loads the export more than once. Untested for NPU memory on the board.
