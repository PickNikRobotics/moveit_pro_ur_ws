# Orbbec Shelf Board Calibration

## At a glance

The 2F-85 workflow uses MoveIt Pro 10.2's [`Calibrate Eye In Hand Camera`](../src/picknik_009_ur5e_2f85_hw_config/objectives/calibrate_wrist_orbbec_on_shelf_board.xml) to solve the wrist Orbbec optical frame while it views the fixed shelf ChArUco board. The solve also estimates the board pose in `world`. The fixed scene D415 is calibrated separately against that same stationary board by the workspace composition [`Calibrate Fixed Camera From Known Board`](../src/picknik_009_ur5e_hw_config/objectives/calibrate_fixed_camera_from_known_board.xml). The scene-camera stage requires the existing D415 optical-to-root TF and a saved arm pose that clears the board from the scene camera's view.

The 2F-85 [`Calibrate Cameras`](../src/picknik_009_ur5e_2f85_hw_config/objectives/calibrate_cameras.xml) checks both camera feeds, then runs the wrist solve and saves the solve, Orbbec mount, and shelf-board pose as candidates. After checking them, the operator applies the wrist mount and, only if the board pose is accepted, the shared `wall_board` record. The scene-camera stage is a separate objective; run it after the shelf-board candidate is accepted and after saving a clear-view arm waypoint. It saves a scene-camera candidate for a separate review and apply step.

## Why this shape

- **Eye-in-hand matches the wrist setup.** The board stays fixed to the shelf while the Orbbec moves with the arm. The native solver estimates both the camera optical pose relative to the chosen arm frame and the board pose in the robot base frame.
- **Native eye-to-hand does not match the scene-camera setup.** It assumes the camera is fixed and the board is mounted on the arm. Here the scene camera and shelf board are both stationary. The workspace's known-board composition uses the wrist-derived board pose plus repeated scene-camera detections instead. The D415's model/root-to-optical TF already exists in the robot model; applying the newly solved scene pose and restarting aligns it to world.
- **The optical result is not the Orbbec root mount.** The native solve returns the optical frame pose in the chosen end-effector frame. The 2F launch needs `wrist_orbbec_link` relative to `d415_mount_link`; the Orbbec helper composes the optical solution with live Orbbec root-to-optical TF, then transforms the root result through the robot kinematic chain to the launch parent.
- **Candidates separate measurement from application.** A bad board pose can corrupt shelf placement; a bad wrist pose changes the Orbbec TF; and a bad scene-camera pose moves the loaded model/TF. The Objectives therefore save candidate values first, while apply Objectives promote only reviewed sections.
- **The shared board record has a wider effect than camera calibration.** `wall_board` is read with `board_offsets.yaml` to place shelving in both hardware configurations. Keep it unchanged if the fixed board has not been shown to reproduce the stored pose and origin; apply a candidate to it only after confirming the existing shelf-offset assumptions.
- **The replacement scene camera retains the current identity.** The replacement D415 keeps the `scene_camera` topics and frames; its reviewed root pose is promoted to `scene_camera_link`.

## Notes and gotchas

- The wrist solver visits saved waypoint names under its prefix. The native generator rotates around the selected frame's +Z axis; the Orbbec viewing axis is not aligned with `grasp_link` +Z, so the solver uses operator-saved waypoints instead. Waypoint names use the `Orbecc Wall` prefix, which the solver searches directly; retain only the intended calibration set under that prefix. Save safe views where the whole board is visible, with orientation variation about at least two axes.
- The feed check requires fresh color frames from both cameras and a fresh registered wrist point cloud before the eye-in-hand solve. The wrist CameraInfo topic is relayed from the Orbbec driver with its eight distortion coefficients correctly declared as `rational_polynomial`; the adapter leaves the measured coefficients unchanged. The native calibration requires raw image and CameraInfo to have equal dimensions and the same non-empty optical frame ID. The camera's RGB-D launch mode must stay enabled; the dual-color preset has no cloud.
- `scene_camera_shelf_clear` is a separately saved, collision-checked arm pose that leaves the shelf board visible to the D415. The scene-camera stage loads the candidate board pose and calibrated planning scene before moving to this waypoint and sampling. The fixed-camera helper depends on the existing `scene_camera_link` to optical-frame TF to convert its optical-frame solution to the root link. It also reuses the last board pose after a detection miss, so the board must be visible in every sample, especially the first.
- Review the wrist solve's used-view count and residuals; a successful tree may have skipped views. The solver needs at least five usable, rotationally diverse samples. A camera result that looks stable numerically can still be wrong if the printed board dimensions, camera intrinsics, optical frame, or image/CameraInfo pairing is wrong.
- Applying the Orbbec mount replaces the YAML section with a pose record, so the 2F launch accepts a missing `temporary` marker as the calibrated state but continues to validate the mount's parent frame. Keep a copy of the previous calibration file before applying, so rollback is possible.
- Candidate and applied poses live in `picknik_009_ur5e_config/objectives/calibration/cell_calibration.yaml`; `Load Calibrated Scene` also uses that package's board-offset YAML to place the shelving. Restart the stack after applying a wrist mount or scene-camera pose; verify the camera overlays, shelf/board placement, and color-registered cloud in the MoveIt Pro 3D Visualizer before using wrist-derived 3D poses for grasping.
